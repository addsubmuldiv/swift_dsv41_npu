# gitcode API 使用指南

> 来源：SKILL.md ⑦ PATCH 章节。Token 等敏感信息从 `scripts/.push_config.json` 读取。

## API 参考

| API | Endpoint | 关键参数 | 注意 |
|-----|----------|----------|------|
| 创建 Issue | `POST /api/v5/repos/Ascend/MegatronAdaptor/issues` | `title`, `body` | **不要传 `labels`**，token 无权限，会 403 |
| 创建 PR | `POST /api/v5/repos/Ascend/MegatronAdaptor/pulls` | `head`(<user>:分支), `base`, `fork_path` | 成功返回 201，`.web_url` 为 MR 链接 |
| PR 评论 | `POST /api/v5/repos/Ascend/MegatronAdaptor/pulls/{number}/comments` | `body` | 评论 `compile` 触发 CI 流水线 |
| 查询 PR | `GET /api/v5/repos/Ascend/MegatronAdaptor/pulls?state=opened&head=<user>:<branch>` | — | 幂等检查用 |
| 查询 Issue | `GET /api/v5/repos/Ascend/MegatronAdaptor/issues?state=opened&search=<keyword>` | — | 幂等检查用 |
| Issue 评论 | `POST /api/v5/repos/Ascend/MegatronAdaptor/issues/{number}/comments` | `body` | 追加每日更新 |
| Auth | `PRIVATE-TOKEN` header | 值从 config 读取 | — |
| 域名 | **`gitcode.com`** | **不是** `api.gitcode.com`（后者被 WAF 拦截 418） | — |
| 关闭 Issue | `PATCH .../issues/{number}` | `{"state_event": "close"}` | **不可用**，gitcode PATCH API 不解析 body |
| 更新 PR 描述 | `PATCH .../pulls/{number}` | **`{"body": "..."}`（必须用 `body`，不是 `description`）** | ✅ 实测可用（2026-08-19，PR #100 更新成功）。`body` 会**整体替换**原描述，需带上完整三 section + `Closes <issue>` |
| JSON 构造 | 使用 `python3 -c "import json"` | 系统没有 `jq` | 所有 JSON 通过 python3 构造 |

## 创建 Issue

将诊断修复报告（DIAGNOSIS_AND_FIX.md）的完整内容写入 Issue。

```bash
# 从 config 读取 token
TOKEN=$(python3 -c "import json; print(json.load(open('scripts/.push_config.json'))['repo']['api_token'])")

python3 << 'PYEOF'
import json

body = """## 问题现象
<从 stderr.log 摘录实际错误栈，标注文件:行号>

## 定位分析

### Breaking commit
<git show 精确 diff，标注 commit SHA 和作者>

### 根因
<崩溃函数内的执行时序分析>

### 触发条件
<什么参数/配置导致代码路径被执行？默认值为什么不触发？>

## 修复方案
<修复代码 + 逻辑说明。修改哪个文件、多少行>

## 验证结果
<实际训练日志摘录：loss 数值、throughput、错误数>

---
*Auto-generated by MegatronAdaptor daily CI*"""

data = {"title": "[daily-ci] <分支> <用例> FAIL — <一句话根因>", "body": body}
with open('/tmp/issue.json', 'w', encoding='utf-8') as f:
    json.dump(data, f, ensure_ascii=False)
PYEOF

# ⚠️ 不要传 labels 字段
# ⚠️ 使用 gitcode.com 域名（不是 api.gitcode.com）
curl -s -X POST "https://gitcode.com/api/v5/repos/Ascend/MegatronAdaptor/issues" \
  -H "Content-Type: application/json" \
  -H "PRIVATE-TOKEN: ${TOKEN}" \
  -d @/tmp/issue.json
# 从响应提取: .number → Issue 编号, .html_url → Issue 链接
```

## 创建 PR（关联 Issue）

> 本节的 API 同样适用于 **Ascend/TransformerEngineNPU**（TE-NPU 契约修复的上游 PR）：
> 只需把 `repos/Ascend/MegatronAdaptor` 换成 `repos/Ascend/TransformerEngineNPU`，
> `fork_path` 换成 `{repo.author_name}/TransformerEngineNPU`（TE-NPU fork 不在 `.push_config.json` 里，
> 按 `{repo.author_name}/TransformerEngineNPU` 构造，token 复用 `repo.api_token`）。
> 完整步骤见 `references/operations.md`「TE-NPU 契约修复提交」。

```bash
TOKEN=$(python3 -c "import json; print(json.load(open('scripts/.push_config.json'))['repo']['api_token'])")
FORK_PATH=$(python3 -c "import json; print(json.load(open('scripts/.push_config.json'))['repo']['fork_path'])")

ISSUE_URL="https://gitcode.com/Ascend/MegatronAdaptor/issues/<number>"
# ⚠️ PR 标题按模板 frontmatter 的 `type(scope): describe` 约定：`fix(adaptor): <简短描述>`
#    （scope 用本仓 adaptor；与 create_issue_pr.py::compose_pr_title 一致）
PR_TITLE="fix(adaptor): <简短描述>"
# ⚠️ PR body 必须按仓库 .gitcode/PULL_REQUEST_TEMPLATE.md 的三个 section 组织（与
#    create_issue_pr.py::compose_pr_body 保持一致）。合入后 body 会作为提交信息进代码仓
#    提交记录，因此**保持精简**，完整诊断放在关联 Issue。
PR_BODY="Closes ${ISSUE_URL}

## What this PR does / why we need it?
修复 <分支> 分支夜间构建失败（<日期>）。失败用例：<test>。根因：<一句话>。

## Does this PR introduce any user-facing change?

No。

## How was this patch tested?

- `<test>`: <N>/<N> 子测试 loss 收敛，loss <init>→<final>，grad_norm <min>–<max>（全非零）
# ⚠️ 写真实验证数字（从重验 stdout 日志提取），不要写 CI 服务器本地路径——对读者信息为 0

---
*Auto-generated by MegatronAdaptor daily CI*"

curl -s -X POST "https://gitcode.com/api/v5/repos/Ascend/MegatronAdaptor/pulls" \
  -H "Content-Type: application/json" \
  -H "PRIVATE-TOKEN: ${TOKEN}" \
  -d "$(python3 -c "
import json
print(json.dumps({
    'head': '${FORK_PATH%/*}:daily_fix_<megatron_branch>',
    'base': '<megatron_branch>',
    'title': '${PR_TITLE}',
    'body': '''${PR_BODY}''',
    'fork_path': '${FORK_PATH}',
}))
")"
```

## 幂等性检查（创建 Issue/PR 前必须执行）

> ⚠️ **优先用脚本 `scripts/create_issue_pr.py --date <date>`**，不要手工 curl 创建 Issue/PR。
> 历史教训：本节下方 `search=${SEARCH_KEYWORD}`（含未编码空格）的 URL 请求会失败返回空，
> 每晚新会话误判"无已存在 Issue"→ 重复建 Issue（main test_attention 一度堆积 7 个）。
> 脚本内部：**Issue 去重粒度 = 问题级**（归一化根因子串匹配，见 create_issue_pr.py
> `find_existing_problem` / `normalize_problem_key`），不再按 `(branch, test)` 前缀——否则
> 同一根因跨分支/用例会裂成多个 Issue（FusedAdam 曾裂 6 个，2026-08-17 修复）；
> PR 因 `head=` 查询过滤不生效改为拉全量 open PR 客户端过滤。
> 下方手工示例仅保留用于参考/调试单次 API 调用。

```bash
TOKEN=$(python3 -c "import json; print(json.load(open('scripts/.push_config.json'))['repo']['api_token'])")
FORK_PATH=$(python3 -c "import json; print(json.load(open('scripts/.push_config.json'))['repo']['fork_path'])")

# 步骤 1: 检查是否已有 open PR
EXISTING_PR=$(curl -s "https://gitcode.com/api/v5/repos/Ascend/MegatronAdaptor/pulls?state=opened&head=${FORK_PATH%/*}:daily_fix_<branch>" \
  -H "PRIVATE-TOKEN: ${TOKEN}")
EXISTING_PR_NUMBER=$(echo "$EXISTING_PR" | python3 -c "import sys,json; prs=json.load(sys.stdin); print(prs[0]['number'] if len(prs)>0 else '')")

# 步骤 2: 检查是否已有 open Issue
SEARCH_KEYWORD="<分支> <用例>"
EXISTING_ISSUE=$(curl -s "https://gitcode.com/api/v5/repos/Ascend/MegatronAdaptor/issues?state=opened&search=${SEARCH_KEYWORD}" \
  -H "PRIVATE-TOKEN: ${TOKEN}")
EXISTING_ISSUE_NUMBER=$(echo "$EXISTING_ISSUE" | python3 -c "import sys,json; issues=json.load(sys.stdin); print(issues[0]['number'] if len(issues)>0 else '')")

# 步骤 3: 分支决策
if [ -n "$EXISTING_PR_NUMBER" ]; then
    echo "已有 open PR #${EXISTING_PR_NUMBER}，跳过创建"
    if [ -n "$EXISTING_ISSUE_NUMBER" ]; then
        echo "已有 open Issue #${EXISTING_ISSUE_NUMBER}，追加评论"
        curl -s -X POST "https://gitcode.com/api/v5/repos/Ascend/MegatronAdaptor/issues/${EXISTING_ISSUE_NUMBER}/comments" \
          -H "Content-Type: application/json" \
          -H "PRIVATE-TOKEN: ${TOKEN}" \
          -d "{\"body\": \"## $(date +%Y-%m-%d) 更新\\n\\n- 失败用例: <test>\\n- 修复 commit: <commit>\\n\\n### 验证报告（<test>）\\n\\n- 子测试: <N>，loss 收敛: <M/N>，梯度: 全非零\\n\\n| 子测试 | loss 首→尾 | grad_norm 范围 | 零梯度次数 |\\n|--------|-----------|---------------|-----------|\\n| 1 | <init> → <final> | <min>–<max> | 0/10 |\\n\\n### 日志原文摘录（重验）\\n\\n\\`\\`\\`text\\n[timestamp] iteration 1/1000 | ... | lm loss: <v> | ... | grad norm: <v>  ← 子测试 1 首\\n[timestamp] iteration 10/1000 | ... | lm loss: <v> | ... | grad norm: <v>  ← 子测试 1 尾\\n\\`\\`\\`\\n\\n---\\n*Auto-generated by MegatronAdaptor daily CI*\"}"
    fi
else
    # 正常创建 Issue + PR 流程
fi
```

## 保存 PR 链接

```bash
python3 -c "
import json
pr_info = {
    'pr_number': <从 API 响应提取>,
    'pr_url': '<PR 的 web_url>',
    'branch': '<megatron_branch>',
    'push_branch': 'daily_fix_<megatron_branch>',
}
with open('output/<YYYY-MM>/<MM-DD>/<branch>/state/pr_info.json', 'w') as f:
    json.dump(pr_info, f, indent=2)
"
```

## 关键规则

- **同一问题（归一化根因）= 同一个 Issue**：跨分支/跨用例/跨天复用并追加每日评论。
  问题 key 来源链：diag_report `extracted_errors[].reason`（test_id 匹配，归一化去
  rank/device/tensor 值/地址）→ verify_report failure_details（按 test 解析）→
  `root_cause` → 都无则退回 `(branch, test)` 前缀匹配（复用既有 issue，防无根因问题每天新建）。
  旧规则「同分支+同用例=同一 Issue」导致同一根因裂成多个 Issue（FusedAdam 曾裂 6 个），已废弃（2026-08-17）
- **Issue 标题格式 `[daily-ci] <根因一句话>`**（不再带分支/用例；分支/用例记录在每日评论）
- 每天 force-push 同一分支会自动更新 PR diff
- 根因变化时需要新建 Issue
- **不要传 `labels` 字段**，token 无权限，会 403
- **使用 `gitcode.com`** 域名，不是 `api.gitcode.com`（后者被 WAF 拦截）
- **关闭 Issue 只能手动**：gitcode PATCH 不解析 `state_event`/`state`（已验证 2026-08-17）
